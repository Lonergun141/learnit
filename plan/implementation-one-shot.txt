===============================================================================
PROJECT GOAL
===============================================================================

LearnIT is a multi-user cloud learning platform.

Users save YouTube videos or web articles through:

1. the LearnIT web application
2. a shared Telegram bot
3. an optional YouTube playlist integration

LearnIT automatically:

1. captures the URL
2. retrieves the transcript/article
3. classifies it into a reusable topic
4. generates:
   - Study Guide
   - Briefing Document
   - Quiz
5. stores everything in Supabase
6. displays the materials inside the LearnIT web app
7. sends a Telegram digest to the correct user

The production application must NOT depend on:

- Baserow
- NotebookLM
- notebooklm-py
- Claude Code
- Claude Cowork
- a local scheduler
- my laptop being online

The previous prototype proved the workflow behavior. This repository is the real
cloud/multi-user implementation.

PHASE 4 — DATABASE HELPERS
===============================================================================

Create reusable updated_at trigger.

Create secure SQL/RPC functions where appropriate.

At minimum implement:

1. claim_learning_jobs(limit, worker_id)

Behavior:

- select queued jobs
- run_after <= now()
- FOR UPDATE SKIP LOCKED
- mark running
- set locked_at
- set locked_by
- increment attempts
- return claimed jobs

This must be concurrency-safe.

2. requeue_stale_jobs()

For jobs stuck running beyond a reasonable lock timeout:

- retry if attempts < max_attempts
- otherwise mark dead

3. enqueue_due_maintenance_jobs()

This should:

- enqueue capture_playlist jobs for users with:
  youtube_capture_enabled=true
  and last poll is due

- enqueue digest jobs when user's LOCAL time reaches digest_hour
  and no digest exists for that user's local date

Timezone handling must be user-specific.

Use IANA timezone names.

Do not allow one invalid timezone string to crash processing for every user.

Fallback to UTC when necessary.

4. create_learning_item_for_current_user(...)

Atomically:
- use auth.uid()
- insert the item if not duplicate
- enqueue fetch job
- return created or existing item

5. create_learning_item_for_user(...)

For trusted service-role use by Telegram/playlist workers.

Do not expose this RPC to ordinary authenticated users.

6. retry_learning_item(item_id)

For the authenticated owner.

Determine correct retry stage from:

status
failure_stage

Examples:

failed fetch:
  set status=new
  enqueue fetch

fetched + classify error:
  enqueue classify

sorted + build error:
  enqueue build_topic

Clear only the relevant retry error.

7. complete_topic_build(...)

Atomic transaction:

- mark previous current topic artifacts is_current=false
- insert new study guide artifact
- insert new briefing artifact
- insert new quiz artifact
- set those new artifacts current
- mark newly sorted items for that topic done
- set built_at
- clear build errors

No partially-written successful build is acceptable.
